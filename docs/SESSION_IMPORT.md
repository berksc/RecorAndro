# Step 1.2 — audio-first session import

Status: implementation, Windows host tests and **Step 1.2 actual-device validation
completed and accepted**. Step 1.1 Android capability acceptance remains recorded
in its own report. Nothing here invokes FFmpeg/ffprobe or qualifies media for processing.

## Input and states

One invocation imports exactly one nonempty regular audio file, optionally with
profile, title and course. Case-insensitive suffix admission is limited to `.m4a`,
`.mp3`, `.wav`, `.aac`. Missing/unreadable/nonregular inputs and source symlinks are
refused. Only the suffix is admitted: actual demuxer, codec, stream, duration,
sample rate, channels and decoding remain uninspected. An invalid recording can
therefore be byte-imported, but cannot yet be called processable. There is no
transcoding, repair, external-source rename or suffix-based media inference.

States are deliberately limited:

| State | Meaning |
| --- | --- |
| `importing` | Session allocated, no valid managed original published in metadata. |
| `imported` | Independent original copy verified by size/SHA-256; media eligibility still `not_inspected`. |
| `failed` | Caught import/publication failure, errors recorded, no valid imported-original reference. |

`visual_count` is always 0 in this step. No photo operation is needed for a valid
audio import. `imported` describes successful import, not a completed processing
or packaging result. Each invocation gets its own UUID session, even for identical
audio; no deduplication, reuse or future processing state machine exists.

```text
<data_root>/sessions/<session_id>/
  session.json
  originals/audio/<safe_leaf>
  generated/
  temp/
```

The source's exact leaf filename is preserved as `audio.original_filename`.
Stored names retain Unicode (including Turkish letters and emoji), normalize to
NFC, replace unsafe separators/control characters and Windows-reserved characters,
avoid reserved device names, and cap the UTF-8 length at 160 bytes while retaining
the suffix. This only names the managed copy; it does not rename user media.
Profile names never become paths. All metadata paths are session-relative; the
external source path is not a processing dependency.

## Deterministic pre-probe storage policy v1

The CLI requires `--provision-seconds D`, an integer from **1 to 604800** (7 days).
Choose an upper provisioning budget rather than an optimistic guessed duration.
It is recorded with `provenance: user_supplied` and
`verified_media_duration: false`. This range is a provisioning input limit, not a
new frozen media-duration eligibility rule. No default duration and no estimate
from byte size, suffix or codec are used.

Let `S` be actual source bytes and `F` currently available bytes on the target
root's filesystem. Reserve:

```text
N = ceil(D / 600) + 1
E = 30000 * D + 65536
G = max(S, 30000 * (D + 5*N) + 65536*N)
T = max(S, E, G)
A = 2 * (S + E + G)  if archive requested OR unresolved; otherwise 0
B = S + E + 2*G + T + A
H = max(268435456, ceil(B / 5))
estimated_required_bytes = B + H
allow iff F >= estimated_required_bytes
```

All arithmetic is integral. `N` is an overprovisioned count allowance, **not a
segmentation plan**. The frozen 600-second useful minimum informs it; the extra
part and five seconds per allowance also overbudget single/last-part overlap.
`30000` is the frozen maximum requested stereo AAC bitrate (192000 bit/s) divided
by eight and multiplied by 1.25. It covers mono conservatively, allows 25% encoder
variation, and adds 64 KiB per estimated container. It does not promise an encoded
size or revise frozen bitrate requests.

| Component | Budget |
| --- | --- |
| Immutable imported original | S; source already present on target volume is already reflected in measured F. |
| Possible normalized output | E, even if later conservative normalization skips. |
| Generated audio | G; max with S also covers a large independent compatible full-length byte copy. |
| Per-part ZIP duplication | G again, with no compression savings assumed. |
| Temporary files | T, one largest artifact; publication reuses the owned temporary inode rather than copying its bytes again. |
| Optional Full Archive | A, two additional copies of original + possible normalized + generated bytes; conservative placeholder for unfrozen archive layout. |
| Headroom | H, larger of 256 MiB or 20% of subtotal; covers metadata, ZIP overhead and allocation variation. |

The margin and formula are **provisional implementation policy**, not newly
frozen product defaults or measured Android storage tuning. Known facts are S,
the filesystem and F at the check. Duration, channels, encoding size, future
archive layout, concurrent storage consumption and D's accuracy are not known.
This is a conservative provisioning check, **not an absolute disk-space
guarantee or reservation**. Runtime ENOSPC still fails safely. Photos and unrelated
sessions' future growth are outside this audio-only estimate. Later stages must
re-evaluate storage using verified media duration, requested modes, actual planned
outputs, selected archive policy and effective encoded sizes before processing.

### Full Archive selection

`--archive requested` and `--archive not_requested` are explicit per-import
selections. `--archive profile` (the CLI default) consults optional local config:

```json
{
  "data_root": "~/recorandro-data",
  "profile_archives": {"lecture": null}
}
```

Missing/null means **unresolved**, reserving the larger archive budget but
recording no ON/OFF selection. A local profile value `true` or `false` resolves
that profile; an explicit CLI selection overrides it. These are user-controlled
local settings, not a frozen Lecture archive default. Unresolved selection must
be resolved before future processing. No archive is created in Step 1.2.

Denial occurs before session allocation and before any original copying/hashing.
Only the explicitly configured root may have been created to measure its
filesystem. The CLI exits 1 and returns required/free bytes and assumptions in
JSON; it does not allocate a fake successful or denied session.

## Integrity and publication

1. Open source read-only without following its final symlink, check regular type,
   suffix, nonzero size and opened identity. Run preflight on the target root.
2. Allocate a collision-safe UUID directory using exclusive creation; atomically
   publish `importing` metadata and create owned layout directories.
3. Exclusively create a uniquely named `.partial` inside that session's `temp/`.
   Copy in 1 MiB chunks, compute source-copy SHA-256, flush and fsync.
4. Re-read/hash the still-open source and temporary import in chunks. Require
   identical sizes and all three hashes, unchanged source identity/size/mtime,
   and unchanged source pathname identity. POSIX also checks ctime. Windows
   Python 3.12 can expose differing path/fd ctime semantics, so Windows relies on
   the other fields and re-hashing. Mutation after the final check is outside any
   external-file snapshot guarantee.
5. Make the owned temporary read-only on POSIX, then move it atomically using
   libc `renameat2(source_dir_fd, source_leaf, destination_dir_fd, final_leaf, 1)`.
   Flag **1 is RENAME_NOREPLACE**: the kernel refuses an existing destination,
   including one created after the advisory existence check. Source/destination
   leaves are validated and directories remain pinned. Verify the final name's
   regular type, inode and size, then fsync destination and source directories.
   A successful rename removes the old temporary name; do not unlink it again.
   No hardlink is created. The external source remains an independent, unchanged
   file. Windows retains its existing checked-directory `os.rename` implementation,
   which refuses an existing target on Windows; it does not gain POSIX descriptor
   guarantees. No ordinary rename/replace or hardlink fallback is allowed on POSIX.
6. Atomically publish `imported` metadata with safe leaf, relative managed path,
   byte size and SHA-256. Only this state and reference designate a valid import.

Metadata publication uses an exclusive uniquely named temporary JSON file,
fsync, then same-directory `os.replace`; readers see complete old or new JSON.
POSIX directory fsync accompanies publication. Imported audio and metadata are
two atomic publications, not a multi-file transaction: if metadata publication
fails after audio publication, a verified orphan may remain, but failed/incomplete
metadata never names it as a valid original.

Caught errors and Ctrl-C produce explicit `failed` metadata and clear valid-file
references. Cleanup only unlinks this operation's known temporary leaf. Existing
sessions are untouched. If failure metadata cannot be persisted (e.g. ENOSPC),
the CLI reports that separately; existing `importing` metadata stays incomplete.
An abrupt kill/power loss may leave `importing` and a temporary or canonical
orphan file; it must not be treated as `imported`. Atomic rename has move semantics:
there is no intermediate second hardlink name. If directory sync or final metadata
publication fails after the move, preserve the verified canonical file as an
unreferenced orphan and record `failed` when possible. Failure cleanup tolerates
an already absent temporary name; this absence is normal after successful rename.
No destination rollback deletes the canonical name. Native errors or unavailable
renameat2 support fail safely without a weaker publication mechanism.
Recovery/orchestration is deferred.

Managed Android operations walk/pin directory descriptors and use `O_NOFOLLOW`
and relative `dir_fd` operations to reject managed symlink redirection. Ancestors
use Linux `O_PATH` so read access to Android system parents is not required;
owned directories use ordinary app permissions. Windows rejects symlinks/junctions
and reparse points and checks directory identity before operations; its fallback
does not claim equivalent protection against malicious concurrent same-user
directory replacement. This is for owned app-private storage, not a shared
directory controlled by another writer. Hashes and future integrity checks remain
authoritative; read-only permissions are not tamper-proof against the owning UID.
The user separately verified that `/data/data`, `/data/user/0` and Termux `$HOME`
are directories, not symlinks, on the actual Redmi. No Android path compatibility
change or workaround is introduced by this correction.

### Native Android publication compatibility correction

Actual device evidence supplied by the user: Python `os.link` is unavailable,
libc `linkat` exists but returns EACCES (errno 13), and libc `renameat2` is available.
A real-device ctypes test of `renameat2(RENAME_NOREPLACE)` returned 0/errno 0 for
first publication and -1/errno 17 (EEXIST) for an existing destination. Destination
bytes were unchanged and the rejected source remained intact. This justifies
replacing the hardlink mechanism; no directory-path workaround is justified.

The POSIX implementation now loads `renameat2` from the process's already linked
libc with `ctypes.CDLL(None, use_errno=True)`. Its typed ABI is
`(int, char*, int, char*, unsigned int) -> int`, using pinned nonnegative directory
descriptors, safe relative leaves and `RENAME_NOREPLACE = 1`. The operation moves
the owned directory entry without following a source symlink. Only a verified
session-owned temporary original is published; source-user paths never enter
this operation. No shell, subprocess, root, hardlink, ordinary rename or replace
fallback is used. ENOSYS, EINVAL, EACCES, EEXIST and other errno values propagate
as OSError subclasses. Missing ctypes/libc symbol support raises StorageError.

The verification record and SHA-256 are preserved, as are size, inode, mtime and
read-only permissions. Rename changes directory-entry/ctime facts as expected;
these are not new schema fields. Both directories are fsynced after verification.
Temporary unlink is no longer part of successful publication. Final session
metadata still uses its separate atomic JSON replacement; failures preserve a
canonical orphan without a valid imported-original metadata reference.

The full Windows host suite after this correction reports **47 tests PASS, no
skips**. Tests cover typed native calls without os.link, native errors and no
fallback, validated descriptors/leaves, move semantics, fsync ordering, collisions,
source/content/inode preservation and final-metadata failure. Windows executes
real atomic moves through a **test-only** Windows syscall transport for sequence
tests; ctypes renameat2 is mocked. This is not native Android execution. Ordinary
